Tester's guide · MAGIS Accounts 0.13.0

Door by door, section by section. Do each test, say how it went, and write a note when something is wrong or unclear. Your answers stay in this page on this device. At the bottom: Copy my notes, Save notes as a file and Print.

Who is testing

Before you start

What the program is

MAGIS Accounts is the program of the MAGIS centres. It has doors: Accounts, Calendar · التقويم, Inventory · الجرد, HR, and Administration · الإدارة. Each door has its own menu. Version 0.13.0 is the new version. You test it before anyone uses it for real.

Two small tags help you: new in 0.13.0 = new since version 0.12.1. Test it as something you meet for the first time. to compare with the old version = it existed before. Check that it still works as it used to. privacy check = someone must not see this. Be strict here.

The data is a COPY, not real

You work on a test copy of the program. The halls, bedrooms, bookings, payments and inventory items with names like “Sample…” are made-up test data. You may add, change, cancel and break things. Nothing is real. Never use the real program for this test. If you are not sure which one you are in, stop and ask Fouad.

How to sign in

Fouad gives you the address of the test copy and several accounts. Each account has one or more roles: Administrator, Director, Accountant, Book holder, Reception, Coordinator (workshops), Store keeper. Ask Fouad which account has which role. Write nobody's password in this page.

Each test says “As: …” when a special role is needed. If no role is written, use the Administrator. To change person: sign out, or use “Test as…” below.

“Test as…” (in Administration)

Open the door Administration · الإدارة. At the top of People and Roles there is a small control Test as… · الدخول باسم…. Choose a person, choose See only or See and act, press Go. You land on that person's own doors page, with a band at the top and a way back. It is the quick way to see the program as another person without their password.

  • In See only the program refuses every change. That is correct, not a problem.
  • A Director using “Test as…” can only look. If a Director can act as someone, that is a problem (write it down).
  • For the tests about signing in, sign in for real with the person's own name and password.

How to reload

If a page looks stuck, old or half empty, reload it: F5 or Ctrl+R (Windows), Cmd+R (Mac), or the reload button of the browser (on a tablet: the round arrow, or pull the page down). Then tell in the note whether reloading fixed it. After you change a role, reload.

Where to write your notes

Here, in this page. Every test has four choices and a note box. The page keeps your answers in the browser of this device: do not clear the browser's data, and use the same browser each time. At the end of each work session press Save notes as a file and keep the files. Send them to Fouad.

How to go through it

  1. Open one door at a time (press its title). Then open a section.
  2. Do the tests of the section in order. Read What to do, do it, and compare with What should happen.
  3. Choose one answer: ✔ Works (it did what is written) · ✘ Problem (it did not) · ➖ Not tried (you could not or did not try) · ❓ Not clear (you do not know if it is right).
  4. If it is a problem, also choose how serious it is, and write a note.
  5. Start with the first page and the doors, then Accounts, Calendar and Inventory (Calendar and Inventory work together). The other doors can follow in any order. One person can do a door in one or two hours.

How serious? Blocks work = I cannot do the job. · Wrong result = it works but gives a wrong number, a wrong person sees it, or it does the wrong thing. · Annoying = it works, but it is slow, ugly, hard or confusing. · Idea = it is not wrong, but I suggest something.

If the program shows a blank page or an error: write what you pressed just before, take a screenshot, reload, and go on.

How to write a good note

A good note lets someone else do the same thing and see the same problem. Write three things, and say who you were:

  1. What you did (which role, which page, what you pressed).
  2. What you expected.
  3. What happened (the words of any message; the number you saw).
Example 1 · a wrong result. “As Reception. Calendar › Week › I dragged over Hall A on Tuesday from 14:00 to 16:00. I expected the booking window to open with those hours. It opened, but the hours were 08:00 to 10:00. Same on a second try.”
Example 2 · nothing happens. “As Accountant. Accounts › Reports › Monthly › Excel. I expected a file with the table of the month. I pressed it twice. No file, no message. Chrome on Windows.”
Example 3 · an idea. “In Quick add the buttons ‘Record and next room’ and ‘Done’ look the same. Maybe use another colour for ‘Done’.”

Short is good. One problem per test. If you are unsure, choose ❓ Not clear and say what confused you.

What to do with a screenshot

A picture often says more than words. Take one of the whole screen when you see a problem. Name the file with the test number, for example CAL-5-4.png (the number is written before each test: CAL 5.4). If you have two pictures, add a letter: CAL-5-4-b.png. Write “screenshot CAL-5-4” in the note. Keep all the pictures in one folder with the saved notes.

  • Windows: Win + Shift + S. Mac: Cmd + Shift + 4. iPad or tablet: the power and volume buttons together.
  • Do not photograph a password. Be careful with names and phone numbers of real people, even in the copy.
Your browser does not keep what you write here (private window, or blocked data). Your notes will be lost when you close the page. Press Save notes as a file often.
